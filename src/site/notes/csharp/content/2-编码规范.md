# 编码规范

#### 1. 命名规范

##### 1.1 大小写约定

| 成员 | 规则 | 示例 |
|------|------|------|
| 命名空间、类、结构、记录、枚举 | `PascalCase` | `OrderService`、`OrderStatus` |
| 接口 | `I` + `PascalCase` | `IOrderService`、`IDisposable` |
| 泛型类型参数 | `T` + `PascalCase` | `TResult`、`TKey` |
| 方法、属性、事件 | `PascalCase` | `CalculateTotal`、`IsValid` |
| 公共常量、静态只读字段 | `PascalCase` | `MaxRetryCount` |
| 私有字段 | `_` + `camelCase` | `_logger`、`_connectionString` |
| 局部变量、参数 | `camelCase` | `totalPrice`、`userId` |
| 异步方法 | `PascalCase` + `Async` | `GetUserAsync` |
| 特性类 | `PascalCase` + `Attribute` | `JsonIgnoreAttribute` |

补充约定：

- 两个字母的缩写全大写（`IO`、`UI`），三个及以上只首字母大写（`Xml`、`Html`）
- 枚举类型用单数（`OrderStatus`），枚举成员用 `PascalCase`
- 布尔成员用 `Is`、`Has`、`Can` 开头，读起来像句子：`if (order.IsPaid)`
- 事件用过去式或现在分词：`OrderCreated`、`Closing`

> **注意**：C# 常量用 `PascalCase`，不要照搬 Java 的 `UPPER_CASE`；接口必须带 `I` 前缀。

##### 1.2 命名示例

```csharp
var service = new OrderService(new ConsoleLogger());
var items = new[] { new OrderItem("键盘", 299m, 2) };
Console.WriteLine($"应付：{service.CalculateTotal(items):C}");

public interface IOrderService
{
    decimal CalculateTotal(IReadOnlyList<OrderItem> items);
}

public sealed class OrderService : IOrderService
{
    private const decimal TaxRate = 0.13m;
    private readonly ILogger _logger;

    public OrderService(ILogger logger) => _logger = logger;

    public string ServiceName { get; } = "订单服务";

    public decimal CalculateTotal(IReadOnlyList<OrderItem> items)
    {
        decimal subtotal = items.Sum(item => item.Price * item.Quantity);
        _logger.Info($"{ServiceName} 小计：{subtotal:C}");
        return subtotal * (1 + TaxRate);
    }
}

public sealed record OrderItem(string Name, decimal Price, int Quantity);

public interface ILogger
{
    void Info(string message);
}

internal sealed class ConsoleLogger : ILogger
{
    public void Info(string message) => Console.WriteLine(message);
}
```

#### 2. 代码风格

##### 2.1 排版规则

- 4 个空格缩进，禁止 Tab；用 `.editorconfig` 统一
- 大括号采用 **Allman** 风格：左大括号另起一行
- 一行一条语句、一行一个声明
- 即使只有一条语句，也保留大括号，避免后续加代码时出错
- 运算符两侧、逗号后加空格；逗号前不加
- 文件编码统一 UTF-8，末尾保留一个空行

##### 2.2 using 与命名空间

```csharp
using System.Globalization;

var culture = CultureInfo.GetCultureInfo("zh-CN");
Console.WriteLine(1234.5m.ToString("C", culture));
```

- `using` 写在文件顶部、`namespace` 之外
- 顺序：`System` → 第三方 → 本项目，组间空一行
- C# 10 起优先使用**文件范围命名空间**：`namespace MyApp.Services;`，只能有一个，且位于 `using` 之后
- 命名空间与文件夹层级对应，避免 `MyApp.Utils.Helpers.Common` 这种过深嵌套
- 不要滥用 `using static` 导入静态成员

#### 3. 注释

##### 3.1 三种注释

- `//` 单行注释，用于解释一行或一段逻辑
- `/* ... */` 多行注释，调试时临时屏蔽代码，不要提交
- `///` XML 文档注释，写在类型或成员上方，可被 IDE 与文档工具提取

##### 3.2 XML 文档注释

```csharp
Console.WriteLine(OrderCalculator.CalculateTotal(99.9m, 3).ToString("C"));

/// <summary>订单金额计算工具。</summary>
public static class OrderCalculator
{
    /// <summary>计算含税总价。</summary>
    /// <param name="unitPrice">单价，必须大于 0。</param>
    /// <param name="quantity">数量，必须大于 0。</param>
    /// <returns>含税总价。</returns>
    /// <exception cref="ArgumentOutOfRangeException">参数不为正数时抛出。</exception>
    public static decimal CalculateTotal(decimal unitPrice, int quantity)
    {
        if (unitPrice <= 0 || quantity <= 0)
        {
            throw new ArgumentOutOfRangeException(nameof(unitPrice), "单价和数量必须大于 0");
        }

        return unitPrice * quantity * 1.13m;
    }
}
```

- 常用标签：`<summary>`、`<param>`、`<returns>`、`<exception>`、`<remarks>`、`<example>`
- `<see cref="OrderItem"/>` 生成可跳转的类型链接
- 重写或实现接口时用 `<inheritdoc/>` 继承基类文档
- 在 `.csproj` 中开启 `<GenerateDocumentationFile>true</GenerateDocumentationFile>` 才会生成 XML 文档，并可对缺失注释给出 CS1591 警告

##### 3.3 注释的原则

- 注释解释**为什么**，代码本身说明**做什么**
- 不写废话：`i++; // i 加一`
- 不保留大段注释掉的死代码，用 Git 历史找回
- TODO 写清负责人与 issue：`// TODO(zhangsan): 支持退款，见 #123`

#### 4. 可空引用类型

项目模板默认 `<Nullable>enable</Nullable>`。开启后：

- `string` 表示**不应为 null**
- `string?` 表示**可能为 null**
- 编译器用警告提示潜在的空引用，如 `CS8602`（可能取消引用 null）、`CS8618`（构造函数未初始化非空属性）

```csharp
string? nickname = null;
Console.WriteLine(nickname?.Length ?? 0);

string SafeTrim(string? input)
{
    ArgumentNullException.ThrowIfNull(input, nameof(input));
    return input.Trim();
}

var user = new User("Tom", null);
Console.WriteLine(user.DisplayName);
Console.WriteLine(SafeTrim("  C#  "));

public sealed class User
{
    public User(string name, string? email)
    {
        Name = name ?? throw new ArgumentNullException(nameof(name));
        Email = email;
    }

    public string Name { get; }
    public string? Email { get; }
    public string DisplayName => Email is null ? Name : $"{Name} <{Email}>";
}
```

- 能用 `?.`、`??` 解决就不要用 `!`
- `!` 只是让编译器闭嘴，运行时该空还是空
- 公共方法入口用 `ArgumentNullException.ThrowIfNull` 做参数校验
- 非空属性可用 `required` 或构造函数强制初始化，避免 `CS8618`

> **注意**：`CS8618` 常见于构造函数未给非空属性赋值，优先用 `required` 或构造函数参数解决，不要用 `null!` 糊弄编译器。

#### 5. var 使用约定

```csharp
var users = new List<string> { "Tom", "Jerry" };         // 右侧类型清晰
var lookup = users.ToDictionary(u => u, u => u.Length);  // LINQ 结果类型冗长
Dictionary<string, int> scores = new();                  // 左侧显式也很常见

var total = 0.1 + 0.2;           // double，未必是想要的结果
decimal money = 0.1m + 0.2m;     // 金额场景显式声明 decimal

Console.WriteLine($"{total:F17} / {money}");
```

- 右侧类型**一眼可见**（`new`、强制转换、`as`）时用 `var`
- 右侧是方法调用、LINQ 查询，且类型重要时，写出显式类型
- 数值字面量慎用 `var`：`var x = 1.0` 是 `double`，不是 `decimal`
- `var` 只能用于局部变量，不能用于字段、参数、返回值
- 团队内保持一致，比“绝对用/不用”更重要

#### 6. 团队约定与常见坑

- **Region 少用**：`#region` 折叠会掩盖类过大的问题，优先拆分文件或类
- 不写 `this.`，除非与局部变量重名
- 单行成员用表达式体：`public string Name => _name;`
- 字符串拼接优先插值 `$"{a}-{b}"`，循环内拼接用 `StringBuilder`
- 字符串比较明确意图：`string.Equals(a, b, StringComparison.OrdinalIgnoreCase)`
- 避免魔法数字，用命名常量或枚举
- `async` 方法以 `Async` 结尾，不要 `async void`（事件处理器除外）
- `catch` 不要吞异常，至少记录日志
- 一个文件通常放一个公开类型，文件名与类型名一致

#### 7. EditorConfig 与自动格式化

##### 7.1 .editorconfig

在仓库根目录放 `.editorconfig`，VS、VS Code、Rider 都会读取：

```text
root = true

[*]
indent_style = space
indent_size = 4
charset = utf-8
insert_final_newline = true
trim_trailing_whitespace = true

[*.cs]
csharp_style_namespace_declarations = file_scoped:suggestion
dotnet_style_qualification_for_field = false:suggestion
dotnet_diagnostic.CS1591.severity = suggestion
```

##### 7.2 自动格式化

```bash
dotnet format
dotnet format --verify-no-changes
```

- `dotnet format` 按 `.editorconfig` 修复空白、using 排序、命名等
- `--verify-no-changes` 在 CI 中使用，有差异则返回非零退出码
- 提交前格式化，减少无意义的 diff

#### 8. 小结

| 主题 | 关键结论 |
|------|----------|
| 命名 | 类型/方法/属性 `PascalCase`，私有字段 `_camelCase`，接口 `I` 前缀 |
| 风格 | 4 空格、Allman 大括号、始终带大括号 |
| 注释 | 公开 API 用 `///` XML 文档，注释解释为什么 |
| 可空 | 开启 `Nullable`，优先 `?.`/`??`，慎用 `!` |
| var | 类型清晰时用，数值字面量与公共 API 写显式类型 |
