# 文件IO

#### 1. 路径与 Path

`Path` 只处理字符串，不访问磁盘；跨平台拼接用 `Path.Combine`。

```csharp
string dir = Path.Combine(Path.GetTempPath(), "csharp-io", "logs");
string file = Path.Combine(dir, "app.log");

Console.WriteLine(Path.GetFileName(file));                 // app.log
Console.WriteLine(Path.GetFileNameWithoutExtension(file)); // app
Console.WriteLine(Path.GetExtension(file));               // .log
Console.WriteLine(Path.GetDirectoryName(file));           // ...\logs
Console.WriteLine(Path.GetFullPath("app.log"));           // 相对转绝对
Console.WriteLine(Path.GetRelativePath(dir, file));       // app.log
```

- `Path.GetTempPath()` 是系统临时目录，适合缓存和测试文件
- `Path.GetFullPath` 依赖 `当前工作目录`，服务里不要假设它是什么

#### 2. File、Directory 与 FileInfo

##### 2.1 静态 API：一次到位

```csharp
string root = Path.Combine(Path.GetTempPath(), "csharp-io-demo");
Directory.CreateDirectory(root);                     // 已存在也不报错
string log = Path.Combine(root, "app.log");
File.WriteAllText(log, "hello");
File.Copy(log, Path.Combine(root, "app.bak"), overwrite: true);
File.Move(Path.Combine(root, "app.bak"), Path.Combine(root, "app.old"), overwrite: true);

foreach (string item in Directory.GetFiles(root, "*.log"))
    Console.WriteLine(item);

File.Delete(log);
Directory.Delete(root, recursive: true);             // 非空目录必须递归删除
```

##### 2.2 实例 API：FileInfo 与 DirectoryInfo

```csharp
var info = new FileInfo(Path.Combine(Path.GetTempPath(), "info-demo.txt"));
if (!info.Exists)
{
    using var writer = new StreamWriter(info.Create());
    writer.Write("FileInfo 示例");
}

info.Refresh();                                      // 重新读取磁盘状态
Console.WriteLine($"大小：{info.Length} 字节，目录：{info.DirectoryName}");

var dir = new DirectoryInfo(Path.GetTempPath());
Console.WriteLine($"临时目录下有 {dir.GetFiles().Length} 个文件");
info.Delete();
```

#### 3. FileStream 字节流

`FileStream` 直接操作 `字节`，适合二进制；文本要在它外面包字符流。

```csharp
string path = Path.Combine(Path.GetTempPath(), "data.bin");

using (var fs = new FileStream(path, FileMode.Create, FileAccess.Write))
{
    fs.Write(new byte[] { 1, 2, 3, 4, 5 });
}

using (var fs = new FileStream(path, FileMode.Open, FileAccess.Read))
{
    var buffer = new byte[3];
    int read = fs.Read(buffer, 0, buffer.Length);
    Console.WriteLine($"长度 {fs.Length}，读取 {read} 字节：{string.Join(",", buffer)}");
    fs.Seek(0, SeekOrigin.Begin);                   // 回到开头
    Console.WriteLine($"首字节：{fs.ReadByte()}");
}
File.Delete(path);
```

- `FileMode`：`Create` 覆盖、`CreateNew` 已存在报错、`Open` 必须存在、`OpenOrCreate` 都行、`Append` 追加、`Truncate` 清空；`FileAccess` 决定读写，`Seek` 可随机访问

> **性能提示**：`FileStream` 自带缓冲，大文件按 4KB~64KB 分块读写比一次读入内存稳定。

#### 4. StreamReader 与 StreamWriter

`StreamReader`/`StreamWriter` 在字节流上加了 `编码` 和 `按行` 处理，读写文本首选。

```csharp
string path = Path.Combine(Path.GetTempPath(), "stream-demo.txt");

using (var writer = new StreamWriter(path, append: false))
    writer.WriteLine("第一行\n第二行");

using (var writer = new StreamWriter(path, append: true))   // 追加模式
    writer.WriteLine("第三行");

using (var reader = new StreamReader(path))
{
    while (reader.ReadLine() is string line)
        Console.WriteLine($"读取：{line}");
}
```

- `append: true` 追加、`false` 覆盖，文件不存在自动创建；`WriteLine` 写平台换行符，`StreamWriter` 有缓冲，`Dispose` 才落盘

#### 5. using 与 IDisposable

文件、流、连接都实现 `IDisposable`；`using` 保证异常时也能释放句柄。

```csharp
string logPath = Path.Combine(Path.GetTempPath(), "app.log");

using (var logger = new FileLogger(logPath))
{
    logger.Write("第一条日志");
}

using var logger2 = new FileLogger(logPath);    // 作用域结束时自动 Dispose
logger2.Write("第二条日志");
Console.WriteLine(File.ReadAllText(logPath));

class FileLogger(string path) : IDisposable
{
    private readonly StreamWriter _writer = new(path, append: true);
    public void Write(string message) => _writer.WriteLine($"{DateTime.Now:HH:mm:ss} {message}");
    public void Dispose() => _writer.Dispose();
}
```

- `using 语句` 适合局部短生命周期，`using 声明` 代码更平；异步资源用 `await using`
- `Dispose` 里只释放资源，不要再抛异常

> **注意**：不 `Dispose` 会导致文件被占用、缓冲数据丢失，Windows 上尤其明显。

#### 6. 文本编码与 BOM

文本文件 = `字节 + 编码`，编码选错会乱码；BOM 是文件头的 `EF BB BF`，用来标记 UTF-8。

```csharp
using System.Text;

string path = Path.Combine(Path.GetTempPath(), "encoding.txt");

File.WriteAllText(path, "中文内容");                          // 默认 UTF-8 无 BOM
Console.WriteLine(BitConverter.ToString(File.ReadAllBytes(path)[..3]));  // E4-B8-AD

File.WriteAllText(path, "中文内容", new UTF8Encoding(true));  // 显式写入 BOM
Console.WriteLine(BitConverter.ToString(File.ReadAllBytes(path)[..3]));  // EF-BB-BF

Console.WriteLine(File.ReadAllText(path));                    // BOM 被自动跳过
Console.WriteLine((int)Encoding.UTF8.GetString(File.ReadAllBytes(path))[0]); // 65279
```

- .NET（Core 起）默认 `UTF-8 无 BOM`；`Encoding.UTF8` 实例带 BOM，`new UTF8Encoding(false)` 明确不带
- `File.ReadAllText`/`StreamReader` 会自动跳过 BOM，`Encoding.GetString` 不会；读写 GBK 需先 `Encoding.RegisterProvider(CodePagesEncodingProvider.Instance)`

> **注意**：跨系统交换文件优先 UTF-8 无 BOM；给 Windows 旧工具（如 Excel 打开的 CSV）才考虑 BOM。

#### 7. 便捷读写与大文件

```csharp
string path = Path.Combine(Path.GetTempPath(), "notes.txt");
File.WriteAllText(path, "Hello\nWorld");
File.AppendAllText(path, "\n第三行");

Console.WriteLine(File.ReadAllText(path));         // 一次性读入整个文件
string[] lines = File.ReadAllLines(path);          // 一次性读入数组
Console.WriteLine($"行数：{lines.Length}");

// 大文件：ReadLines 惰性返回 IEnumerable<string>，一次只持有一行
int no = 0;
foreach (string line in File.ReadLines(path))
    Console.WriteLine($"{++no}: {line}");
```

- `WriteAllText`/`ReadAllText`/`AppendAllText` 是最短路径，适合配置文件、小文本
- `ReadAllLines` 返回数组，`ReadLines` 是惰性枚举

> **性能提示**：几百 MB 的日志用 `ReadAllLines` 可能直接 OOM，逐行读取内存占用稳定。

#### 8. 异步 IO

IO 等待时线程应被释放，用 `async`/`await` 加异步 API，而不是 `Task.Run` 包同步读写。

```csharp
using System.Text;

string path = Path.Combine(Path.GetTempPath(), "async-demo.txt");
await File.WriteAllTextAsync(path, "异步写入\n第二行", Encoding.UTF8);
Console.WriteLine(await File.ReadAllTextAsync(path));
await using (var source = new FileStream(path, FileMode.Open, FileAccess.Read, 4096, useAsync: true))
await using (var target = new FileStream(path + ".bak", FileMode.Create, FileAccess.Write, 4096, useAsync: true))
{
    await source.CopyToAsync(target);
}
Console.WriteLine(new FileInfo(path + ".bak").Length);
File.Delete(path);
File.Delete(path + ".bak");
```

- 快捷方法：`ReadAllTextAsync`、`WriteAllTextAsync`、`ReadAllLinesAsync`、`AppendAllTextAsync`；自己开 `FileStream` 要传 `useAsync: true`，否则只是假异步

> **注意**：不要用 `.Result`/`.Wait()` 等异步方法，容易阻塞线程池，在同步上下文里还会死锁。

#### 9. System.Text.Json 序列化

```csharp
using System.Text.Json;
using System.Text.Json.Serialization;

var user = new User { Id = 1, Name = "张三", Email = "zhang@example.com" };
var options = new JsonSerializerOptions
{
    WriteIndented = true,
    PropertyNamingPolicy = JsonNamingPolicy.CamelCase
};
string json = JsonSerializer.Serialize(user, options);
Console.WriteLine(json);

var back = JsonSerializer.Deserialize<User>(json)!;
Console.WriteLine($"{back.Id} {back.Name} {back.Email}");

class User
{
    public int Id { get; set; }
    [JsonPropertyName("display_name")] public string Name { get; set; } = "";
    public string Email { get; set; } = "";
}
```

- 默认属性名原样输出，`CamelCase` 策略适合 Web API；`[JsonPropertyName]` 优先级更高
- `WriteIndented` 只影响可读性；反序列化失败抛 `JsonException`，字段缺失保持默认值

> **性能提示**：高频序列化可复用 `JsonSerializerOptions`（线程安全），并用源生成 `JsonSerializerContext` 避免反射开销。

#### 10. 临时文件与异常

```csharp
string path = Path.Combine(Path.GetTempPath(), $"demo-{Guid.NewGuid():N}.txt");

try
{
    File.WriteAllText(path, "临时数据");
    Console.WriteLine(File.ReadAllText(path));
    File.ReadAllText(Path.Combine(path, "sub", "missing.txt"));   // 把文件当目录用
}
catch (DirectoryNotFoundException ex) { Console.WriteLine($"目录不存在：{ex.Message}"); }
catch (FileNotFoundException ex) { Console.WriteLine($"文件不存在：{ex.FileName}"); }
catch (IOException ex) { Console.WriteLine($"IO 错误：{ex.Message}"); }
catch (UnauthorizedAccessException ex) { Console.WriteLine($"无权限：{ex.Message}"); }
finally
{
    if (File.Exists(path)) File.Delete(path);
}
```

- 捕获顺序必须 `从具体到宽泛`，`IOException` 要放在其子类之后
- `IOException` 覆盖文件被占用、磁盘满、路径过长；`UnauthorizedAccessException` 表示权限不足
- 临时文件用 `Path.GetTempPath()` + `Guid` 命名，避免并发冲突

> **注意**：`File.Exists` 只能"尽力而为"，检查完到读取之间文件可能已被删除（TOCTOU），关键逻辑仍要靠 `try/catch`。

#### 11. 小结

| 知识点 | 关键结论 |
|--------|----------|
| `Path` | 只处理字符串路径，跨平台用 `Combine` |
| 静态 API | `File`/`Directory` 一次到位，适合简单场景 |
| 实例 API | `FileInfo` 有缓存，改动后要 `Refresh()` |
| `FileStream` | 字节级读写，`FileMode` 决定打开方式 |
| 字符流 | `StreamReader`/`StreamWriter` 处理编码与按行 |
| `using` | 确保句柄释放，异步用 `await using` |
| 编码 | 默认 UTF-8 无 BOM，BOM 为 `EF BB BF` |
| 大文件 | 逐行读，别用 `ReadAllLines` 全量装入 |
| 异步 IO | 用 `ReadAllTextAsync` 等，别用 `Task.Run` 包同步 IO |
| JSON | `JsonSerializer` + `JsonSerializerOptions` |
