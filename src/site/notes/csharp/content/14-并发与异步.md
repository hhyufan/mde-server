# 并发与异步

#### 1. 线程与线程池

`Thread` 是手动线程；`ThreadPool` 复用线程，`Task` 默认就运行在线程池上。

```csharp
var worker = new Thread(() => Console.WriteLine($"线程 {Environment.CurrentManagedThreadId} 启动"))
    { IsBackground = true, Name = "worker" };
worker.Start();
worker.Join();                                  // 阻塞等待线程结束

ThreadPool.QueueUserWorkItem(state =>
    Console.WriteLine($"线程池处理：{state}"), "job-1");
Thread.Sleep(200);                              // 演示用：等线程池输出
```

- 前台线程会阻止进程退出，`IsBackground = true` 的线程不会
- 线程池适合短任务，长时间阻塞会拖垮池子；业务并发优先用 `Task`

#### 2. Task 与 Task<T>

`Task` 表示一个 `异步操作`，可能已完成、正在运行或将来完成；`Task<T>` 额外携带结果。

```csharp
Task<int> task = Task.Run(() =>
{
    Thread.Sleep(300);
    return 42;
});

Console.WriteLine(task.Status);          // WaitingToRun / Running
Console.WriteLine(task.Result);          // 42，阻塞等待
Console.WriteLine(task.Status);          // RanToCompletion
```

- `.Result`/`.Wait()` 会 `阻塞` 当前线程，异常被包成 `AggregateException`
- 想同步取结果又不包装异常，用 `task.GetAwaiter().GetResult()`

> **注意**：`Task` 不是线程，只是"承诺"；同一个 `Task` 可以 `await` 多次，结果会被缓存。

#### 3. async/await 的本质

`async` 方法会被编译器改写成 `状态机`：遇到未完成的 `await` 就 `返回` 调用方，完成后通过 `MoveNext` 恢复，所以等待期间 `不占用线程`。

```csharp
Console.WriteLine($"调用前：{Environment.CurrentManagedThreadId}");
await DemoAsync();
Console.WriteLine("主线程继续");

static async Task DemoAsync()
{
    Console.WriteLine($"进入：{Environment.CurrentManagedThreadId}");
    await Task.Delay(500);                  // 让出线程，不阻塞
    Console.WriteLine($"await 之后：{Environment.CurrentManagedThreadId}");
}
```

- `async` 方法返回 `Task`、`Task<T>` 或 `ValueTask`，`async void` 只用于事件处理器
- 状态机把局部变量提升为字段，`await` 前后可能在不同线程上继续

> **注意**：`async` 本身不会开线程。真正跑 CPU 代码的是 `Task.Run` 或调用方线程。

#### 4. Task.Run：CPU 密集与 IO 密集

- **CPU 密集**：用 `Task.Run` 丢到线程池，避免阻塞 UI 线程
- **IO 密集**：用原生异步 API（`ReadAllTextAsync`、`HttpClient.GetAsync`），不要 `Task.Run` 包同步 IO

```csharp
// CPU 密集：交给线程池
int sum = await Task.Run(() => SumTo(50_000_000));
Console.WriteLine(sum);

// IO 密集：异步 API 才真正释放线程
string path = Path.Combine(Path.GetTempPath(), "io-demo.txt");
await File.WriteAllTextAsync(path, "io");
Console.WriteLine(await File.ReadAllTextAsync(path));

static int SumTo(int n) { int s = 0; for (int i = 1; i <= n; i++) s += i; return s; }
```

> **性能提示**：`Task.Run` 包同步 IO 只会占一个线程干等，既浪费线程又没提升吞吐。

#### 5. 取消：CancellationToken

异步操作要支持取消：调用方传 `CancellationToken`，被调方定期检查并抛 `OperationCanceledException`。

```csharp
using var cts = new CancellationTokenSource(TimeSpan.FromMilliseconds(250));
try { await CountAsync(cts.Token); }
catch (OperationCanceledException) { Console.WriteLine($"已取消：{cts.IsCancellationRequested}"); }

static async Task CountAsync(CancellationToken token)
{
    for (int i = 0; i < 5; i++)
    {
        token.ThrowIfCancellationRequested();
        await Task.Delay(100, token);       // Delay 也会响应取消
    }
}
```

- `Cancel()` 主动取消，`CancelAfter` 定时取消，`ThrowIfCancellationRequested()` 是协作检查点
- 取消不是错误，`Task` 状态会变成 `Canceled`

#### 6. 组合任务：WhenAll 与 WhenAny

```csharp
var tasks = new[] { DelayAsync("A", 300), DelayAsync("B", 100) };
string[] results = await Task.WhenAll(tasks);
Console.WriteLine(string.Join(",", results));      // A,B，按输入顺序

Task<string> first = await Task.WhenAny(DelayAsync("X", 500), DelayAsync("Y", 100));
Console.WriteLine($"最先完成：{await first}");      // Y

static async Task<string> DelayAsync(string name, int ms) { await Task.Delay(ms); return name; }
```

- `WhenAll` 等全部完成，结果顺序与传入一致；任一失败则 `await` 抛第一个异常
- `WhenAny` 等第一个完成，返回那个已完成的 `Task`，不会取消其余任务

> **注意**：`WhenAny` 剩下的任务仍在后台跑，需要自己管理它们的生命周期。

#### 7. 线程同步：lock、Monitor、Interlocked

共享可变状态必须同步，否则 `++` 这种"读-改-写"会丢更新。

```csharp
int counter = 0, atomic = 0;
object gate = new();
var threads = new[] { new Thread(Work), new Thread(Work), new Thread(Work), new Thread(Work) };
foreach (var t in threads) t.Start();
foreach (var t in threads) t.Join();
Console.WriteLine($"lock：{counter}，Interlocked：{atomic}");   // 都是 400000

void Work()
{
    for (int i = 0; i < 100_000; i++) { lock (gate) counter++; Interlocked.Increment(ref atomic); }
}
```

- `lock` 等价于 `Monitor.Enter` + `try/finally` + `Monitor.Exit`
- `Interlocked` 提供无锁原子操作：`Increment`、`Add`、`Exchange`、`CompareExchange`
- 锁对象应是 `private readonly object`，不要锁 `this`、`string` 或值类型

> **注意**：`lock` 只保证互斥，跨进程同步要用 `Mutex`；持锁时不要执行慢操作。

#### 8. SemaphoreSlim 限流

`SemaphoreSlim` 限制同时执行的并发数，适合控制下游压力。

```csharp
using var semaphore = new SemaphoreSlim(2);        // 最多 2 个并发
var tasks = new List<Task>();
for (int i = 1; i <= 5; i++)
{
    int id = i;
    tasks.Add(Task.Run(async () =>
    {
        await semaphore.WaitAsync();
        try { Console.WriteLine($"任务 {id} 开始"); await Task.Delay(200); }
        finally { semaphore.Release(); }           // 必须释放
    }));
}
await Task.WhenAll(tasks);
```

- `Wait()` 同步等待，`WaitAsync()` 异步等待；异步代码一律用后者
- `Release()` 必须放在 `finally`，否则异常会让计数永久少一个

#### 9. 并发集合

普通 `Dictionary`/`List` 多线程读写会损坏内部结构，应改用 `System.Collections.Concurrent`。

```csharp
var dict = new ConcurrentDictionary<string, int>();
dict.TryAdd("a", 1);
dict.AddOrUpdate("a", 1, (_, old) => old + 1);
Console.WriteLine($"a={dict["a"]}, b={dict.GetOrAdd("b", 100)}");

var queue = new ConcurrentQueue<int>();
queue.Enqueue(1);
Console.WriteLine(queue.TryDequeue(out int first));

using var buffer = new BlockingCollection<string>(2);   // 有界队列
var producer = Task.Run(() => { for (int i = 1; i <= 3; i++) buffer.Add($"消息{i}"); buffer.CompleteAdding(); });
var consumer = Task.Run(() => { foreach (string item in buffer.GetConsumingEnumerable()) Console.WriteLine(item); });
await Task.WhenAll(producer, consumer);
```

- `ConcurrentDictionary`：`AddOrUpdate`、`GetOrAdd` 是原子复合操作
- `ConcurrentQueue`/`ConcurrentStack`/`ConcurrentBag`：`TryDequeue`/`TryPop` 无锁
- `BlockingCollection`：有界阻塞队列，天然实现生产者-消费者；异步消费可用 `Channel<T>`

#### 10. Parallel.For

数据并行用 `Parallel.For`/`ForEach`，内部自动分区并调度到线程池。

```csharp
long total = 0;
Parallel.For(1, 1_000_001, i => Interlocked.Add(ref total, i));
Console.WriteLine(total);                          // 500000500000

var options = new ParallelOptions { MaxDegreeOfParallelism = 4 };
Parallel.ForEach(new[] { "a.txt", "b.txt", "c.txt" }, options,
    file => Console.WriteLine($"处理 {file}，线程 {Environment.CurrentManagedThreadId}"));
```

- 循环体必须线程安全，累加用 `Interlocked` 或 `lock`
- `MaxDegreeOfParallelism` 控制并发度，默认等于 CPU 核数；`Parallel.For` 会阻塞到全部完成

> **性能提示**：`Parallel` 适合 CPU 密集的大批量计算；IO 密集用它只会占满线程池。

#### 11. 死锁

死锁的经典成因：多个线程以 `不同顺序` 获取多把锁，互相等待。

```csharp
// 1. 同步等待异步：控制台会阻塞，UI/ASP.NET 上下文可能死锁
Task<string> task = GetDataAsync();
Console.WriteLine(task.Result);

// 2. 两把锁交叉获取：经典死锁
object a = new(), b = new();
var t1 = Task.Run(() => { lock (a) { Thread.Sleep(100); lock (b) { } } });
var t2 = Task.Run(() => { lock (b) { Thread.Sleep(100); lock (a) { } } });
Console.WriteLine(Task.WaitAll(new[] { t1, t2 }, 1000) ? "完成" : "超时，可能死锁");

static async Task<string> GetDataAsync() { await Task.Delay(100); return "data"; }
```

- 预防：所有线程按 `相同顺序` 加锁、缩小锁范围、用超时 `Monitor.TryEnter`
- 不要在持锁时调用外部代码、`await` 或阻塞 IO

> **注意**：控制台没有同步上下文，`.Result` 通常只是阻塞；WPF/ASP.NET 老代码里它会让等待线程和续体互相等待，直接死锁。

#### 12. 常见陷阱与 ConfigureAwait

```csharp
try
{
    FireAndForget();                    // async void：异常调用方 try/catch 捕不到
    await SafeAsync();                  // async Task：异常能被 catch
}
catch (InvalidOperationException ex) { Console.WriteLine($"捕获：{ex.Message}"); }

await Task.Delay(10).ConfigureAwait(false);   // 类库代码不关心上下文

static async void FireAndForget() => await Task.Delay(50);
static async Task SafeAsync()
{
    await Task.Delay(50);
    throw new InvalidOperationException("来自 async Task");
}
```

- `async void` 无法被 `await`，异常会抛到线程池，通常导致进程退出；只用于事件处理器
- 不要用 `.Result`/`.Wait()` 混合同步与异步，会阻塞甚至死锁
- `ConfigureAwait(false)` 表示续体不必回到原上下文，类库内部推荐使用

> **注意**：`Task.Run` 不是"异步"的同义词；它只是把同步代码挪到线程池，真正的异步 IO 不占线程。

#### 13. 小结

| 知识点 | 关键结论 |
|--------|----------|
| 线程 | `Thread` 手动创建，后台线程不阻止进程退出 |
| `Task` | 表示异步操作，`.Result` 会阻塞并包装异常 |
| `async/await` | 状态机 + 让出线程，`async` 本身不开线程 |
| CPU vs IO | CPU 用 `Task.Run`，IO 用原生异步 API |
| 取消 | `CancellationTokenSource` + `ThrowIfCancellationRequested` |
| 组合 | `WhenAll` 等全部，`WhenAny` 等第一个 |
| 同步 | `lock` 互斥，`Interlocked` 原子操作 |
| 限流 | `SemaphoreSlim` 控制并发数，`finally` 释放 |
| 并发集合 | `ConcurrentDictionary`/`BlockingCollection` |
| 并行 | `Parallel.For` 适合 CPU 密集计算 |
| 陷阱 | 死锁、`async void`、`.Result` 阻塞 |
