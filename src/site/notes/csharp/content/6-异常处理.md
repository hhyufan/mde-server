# 异常处理

#### 1. 异常概述

##### 1.1 什么是异常

`异常`是程序在 `运行期` 发生的 `错误事件`，它打断正常流程，把控制权交给最近的 `catch`。异常对象携带 `Message`、`StackTrace`、`InnerException`；无人捕获时运行时打印 `Unhandled exception` 与堆栈并终止进程。

```csharp
try { int z = 0; Console.WriteLine(1 / z); }           // DivideByZeroException
catch (DivideByZeroException) { Console.WriteLine("除零"); }

int[] arr = { 1, 2, 3 };
try { Console.WriteLine(arr[5]); }                     // IndexOutOfRangeException
catch (IndexOutOfRangeException) { Console.WriteLine("索引越界"); }

string? text = null;
try { Console.WriteLine(text.Length); }                // NullReferenceException
catch (NullReferenceException) { Console.WriteLine("空引用"); }

try { int n = int.Parse("abc"); }                      // FormatException
catch (FormatException) { Console.WriteLine("格式错误"); }
```

> **注意**：C# 没有 Java 的 `checked exception`，异常既不强制声明也不强制捕获。这既是自由，也意味着 `try/catch` 全靠自觉。
#### 2. 异常层次结构

所有可捕获的异常都继承自 `System.Exception`（一个 `class`），自定义异常也从这里派生。

| 类型 | 含义 |
|------|------|
| `System.Exception` | 一切异常的根 |
| `ArgumentException` | 参数非法；派生 `ArgumentNullException`、`ArgumentOutOfRangeException` |
| `InvalidOperationException` | 当前对象状态不允许该操作 |
| `FormatException` / `OverflowException` | 解析失败 / 数值溢出 |
| `IOException` 及 `FileNotFoundException` | 文件与流 |
| `TimeoutException` / `OperationCanceledException` | 超时 / 被取消 |

常见触发点：字典用不存在的 key 索引抛 `KeyNotFoundException`；遍历 `List` 时增删抛 `InvalidOperationException`；错误的强转或拆箱抛 `InvalidCastException`。`SystemException` / `ApplicationException` 是历史分层，业务异常不要继承它们。

#### 3. try / catch / finally

##### 3.1 基本结构

```csharp
try
{
    Console.WriteLine("打开连接");
    throw new InvalidOperationException("命令执行失败");   // 模拟业务失败
}
catch (InvalidOperationException ex)
{
    Console.WriteLine($"处理异常：{ex.Message}");          // Message 给用户
}
finally
{
    Console.WriteLine("释放连接");                        // 无论成败都执行
}
```

`try` 只包住 `可能抛异常` 的最小范围；`catch` 按类型匹配，可写多个也可只留 `try/finally`；`finally` 里的代码 `try` 中 `return` 也拦不住。

> **注意**：不要在 `finally` 里 `return`、`throw` 或修改返回值——它会覆盖 `try`/`catch` 已确定的结果，也会吞掉正在传播的异常。

##### 3.2 多个 catch 的顺序

```csharp
foreach (string input in new[] { "5", "0", "abc" })
{
    try
    {
        int n = int.Parse(input);                    // 可能 FormatException
        Console.WriteLine($"{input} -> {100 / n}");  // 可能 DivideByZeroException
    }
    catch (FormatException ex)                       // 具体类型在前
    {
        Console.WriteLine($"格式错误：{ex.Message}");
    }
    catch (DivideByZeroException)
    {
        Console.WriteLine("除数不能为 0");
    }
    catch (Exception ex) { Console.WriteLine($"其他异常：{ex.GetType().Name}"); }   // 兜底
}
```

> **注意**：`catch` 必须 `子类在前、父类在后`，否则编译报错 `CS0160: A previous catch clause already catches all exceptions of this or of a super type`。

#### 4. throw 与重抛

##### 4.1 throw 与 throw;

```csharp
static void Save(string name)
{
    if (string.IsNullOrEmpty(name))
    {
        throw new ArgumentException("文件名不能为空", nameof(name));   // 带参数名
    }

    try
    {
        throw new UnauthorizedAccessException("没有写权限");
    }
    catch (UnauthorizedAccessException ex)
    {
        // throw;        原样重抛，堆栈保留，指向 Save 内部
        // throw ex;     堆栈被重置到这一行，丢失原始现场
        Console.WriteLine($"记录日志：{ex.Message}");
        throw;            // 记完日志继续向上抛，调用方的堆栈仍指向这里
    }
}
```

- `throw;` 保留原始堆栈，适合"记录后继续抛"
- `throw ex;` 把堆栈重置到当前行，**禁止使用**
- 跨层转换类型时写 `throw new XxxException("下单失败", ex)`，原异常进 `InnerException`

##### 4.2 when 异常过滤

`when` 在进入 `catch` 前判断：条件为 `false` 就不进 `catch`，异常继续向上传播，**堆栈不被破坏**。

```csharp
static void Call(int code)
{
    for (int i = 0; i < 2; i++)
    {
        try
        {
            if (code == 500) throw new HttpRequestException("服务端错误");
            if (code == 404) throw new HttpRequestException("资源不存在");
            Console.WriteLine("请求成功");
            return;
        }
        catch (HttpRequestException ex) when (code == 500 && i == 0)
        {
            Console.WriteLine($"第 {i + 1} 次重试：{ex.Message}");   // 只对 500 重试
        }
        catch (HttpRequestException ex)
        {
            Console.WriteLine($"直接失败：{ex.Message}");
            return;
        }
    }
}

Call(500);      // 重试一次后失败
```

> **性能提示**：`when` 比"先进 `catch`、再判断、再 `throw;`"更省——条件不成立时连 `catch` 都不进入，也不展开新堆栈。

#### 5. 自定义异常

##### 5.1 定义

继承 `Exception`（或业务基类），命名以 `Exception` 结尾，惯例提供无参、`message`、`message + inner` 三个构造函数，并把业务上下文做成只读属性。

```csharp
public sealed class OrderAmountException : Exception
{
    public decimal Amount { get; }

    public OrderAmountException(decimal amount, Exception? inner = null)
        : base($"订单金额非法：{amount}", inner) => Amount = amount;
}

try
{
    throw new OrderAmountException(-1m);
}
catch (OrderAmountException ex)
{
    Console.WriteLine($"{ex.Message}，Amount = {ex.Amount}");   // 上层能拿到业务字段
}
```

##### 5.2 业务异常基类

```csharp
public abstract class BusinessException : Exception
{
    public string Code { get; }

    protected BusinessException(string code, string message)
        : base(message) => Code = code;
}

public sealed class UserNotFoundException : BusinessException
{
    public UserNotFoundException(string userId)
        : base("USER_NOT_FOUND", $"用户不存在：{userId}") { }
}

try
{
    throw new UserNotFoundException("u001");
}
catch (BusinessException ex)             // 一次捕获所有业务异常
{
    Console.WriteLine($"[{ex.Code}] {ex.Message}");
}
```

#### 6. using、IDisposable 与 try-finally

```csharp
public sealed class TempFile(string path) : IDisposable
{
    public string Path { get; } = path;
    public void Dispose() => Console.WriteLine($"删除 {Path}");
}

var manual = new TempFile("a.tmp");          // 1. 手写 try-finally
try { Console.WriteLine("使用 a.tmp"); }
finally { manual.Dispose(); }

using (var scoped = new TempFile("b.tmp"))   // 2. using 语句
    Console.WriteLine("使用 b.tmp");

using var last = new TempFile("c.tmp");      // 3. using 声明：作用域末尾释放
Console.WriteLine("使用 c.tmp");
```

| 方式 | 写法 | 释放时机 |
|------|------|----------|
| `try/finally` | `try { } finally { x.Dispose(); }` | 手动控制 |
| `using` 语句 | `using (var x = ...) { }` | 离开 `{}` |
| `using` 声明 | `using var x = ...;` | 离开当前作用域 |
| 异步 | `await using var x = ...;` | 配 `IAsyncDisposable` |

> **注意**：多个 `using` 嵌套时，释放顺序与声明顺序 `相反`（后声明先释放），和 `finally` 的栈式展开一致。

#### 7. ExceptionDispatchInfo

跨线程、跨 `Task` 或延迟处理时，`throw ex;` 会丢堆栈。`ExceptionDispatchInfo` 能 `Capture` 现场后原样重抛。

```csharp
using System.Runtime.ExceptionServices;

try
{
    throw new InvalidOperationException("原始错误");
}
catch (InvalidOperationException ex)
{
    ExceptionDispatchInfo pending = ExceptionDispatchInfo.Capture(ex);   // 保存现场
    try { pending.Throw(); }                                             // 原样重抛
    catch (InvalidOperationException again)
    {
        Console.WriteLine(again.StackTrace?.Contains("ExceptionDispatchInfo"));   // False
    }
}
```

> **注意**：`await` 与 `Task.Wait()` 内部已做过等价处理；只有自己实现"异常暂存""异步转同步"时才需要手动 `Capture`。

#### 8. 不要用异常控制流程

异常的代价在于 `构造对象` + `抓取堆栈` + `栈展开`，比普通分支慢几个数量级。可预期的失败要用返回值表达。

```csharp
// ❌ 反例：用异常判断输入是否合法，内部要抛一次异常
static bool IsNumberByException(string input)
{
    try { int.Parse(input); return true; }
    catch (FormatException) { return false; }
}

// ✅ 正例：TryXxx 模式，失败返回 false，不抛异常
static bool IsNumber(string input) => int.TryParse(input, out _);

Console.WriteLine(IsNumberByException("abc"));   // False
Console.WriteLine(IsNumber("abc"));              // False，纯分支
```

判断标准：输入格式可能错用 `TryParse` / `TryGetValue`；查找不到返回 `null`、`false` 或空集合；调用方 bug（`null` 参数、越界）才 `throw`；真正的环境故障（IO 断开、网络超时）`throw` + 重试或上报。

> **性能提示**：`try` 块在"不抛异常"时几乎零成本，昂贵的只有 `throw` 那一刻。可以给整段逻辑套粗粒度的 `try`，但不要用抛异常驱动正常分支。

#### 9. 小结

| 知识点 | 关键结论 |
|--------|----------|
| 层次 | 一切异常继承 `System.Exception`，无 checked exception |
| 结构 | `try` 包最小范围，`catch` 子类在前，`finally` 收尾 |
| 重抛 | 用 `throw;` 保留堆栈，禁止 `throw ex;` |
| 过滤 | `when` 条件不成立时不进 `catch`，堆栈更干净 |
| 资源 | 优先 `using` / `await using` 替代手写 `try-finally` |
| 流程 | 可预期失败用 `TryXxx`，不用异常驱动正常分支 |
